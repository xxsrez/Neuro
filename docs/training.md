# Обучение и оценка

Статус: план реализации. Формула потерь и графики обсуждены с пользователем;
размер пакета, скорость обучения и бюджет — стартовые предложения.
Данные описаны в [спецификации](specs/point-motion.md), модель — в
[архитектуре](architecture.md).

## Функция потерь

Для пакета B примеров используем нормализованные координаты:

```text
L = sum_i ((x_pred_i - x_target_i)^2 +
           (y_pred_i - y_target_i)^2) / (2 * B)

dL/dx_pred_i = (x_pred_i - x_target_i) / B
dL/dy_pred_i = (y_pred_i - y_target_i) / B
```

Это средняя квадратичная ошибка по всем 2B скалярным выходам.
Обучение сначала использует только конечные координаты: потерь на скрытых
состояниях нет. Масштабирование градиента на размер пакета выполняется
ровно один раз. Для неполного последнего пакета берётся его реальный размер.

## Один цикл обучения

1. Создать независимые воспроизводимые генераторы данных, начальных весов
   и перемешивания. Зафиксировать конфигурацию и исходную ошибку до обучения.
2. В начале эпохи перемешать только обучающие индексы.
3. Для пакета из 64 примеров обнулить накопленные градиенты.
4. Для каждого примера выполнить прямой проход с сохранением необходимых
   промежуточных значений, посчитать потерю и выполнить ручной обратный проход.
5. Накопить градиенты при неизменных весах внутри пакета и один раз обновить
   веса оптимизатором. Усреднение согласовать с формулой выше.
6. После эпохи без обновления весов оценить полную обучающую и валидационную
   выборки, записать метрики и при улучшении валидации сохранить лучшие веса.

Начальный бюджет — 200 эпох. При 8 192 примерах и пакете 64 это
128 обновлений за эпоху, всего 25 600. До полного запуска измерить время
нескольких эпох; это не обещание времени или сходимости.
Не добавлять скрытое обрезание градиентов: NaN или бесконечности останавливают
опыт с диагностикой. Обрезание, если понадобится, оформляется отдельной настройкой.

## Оптимизаторы

SGD реализуется первым как простой контроль: theta = theta - lr * grad.
Первый основной опыт предлагается провести с Adam: lr = 0.001,
beta1 = 0.9, beta2 = 0.999, epsilon = 1e-8. Эти числа подлежат проверке.

```text
t = t + 1                     # один раз на обновление пакета
m = beta1 * m + (1 - beta1) * grad
v = beta2 * v + (1 - beta2) * grad^2
m_hat = m / (1 - beta1^t)
v_hat = v / (1 - beta2^t)
theta = theta - lr * m_hat / (sqrt(v_hat) + epsilon)
```

Все операции выполняются поэлементно для каждого параметра; m и v начинают
с нуля. Это Adam без добавленного штрафа или убывания весов. Для SGD скорость
подбирается отдельно по валидации: одинаковая скорость двух оптимизаторов
не означает сопоставимые условия. Формулы проверять на ручных примерах.

## Метрики и графики

- Потери на полном обучающем наборе и валидации — две кривые по эпохам,
  включая точку до первого обновления. Каждая пара рассчитана при одинаковых
  текущих весах. Потери отдельных пакетов — отдельная шумная диагностическая кривая.
- Среднее евклидово расстояние до правильной конечной точки в исходных
  координатах: mean(sqrt(dx^2 + dy^2)), после обратного масштабирования.
- Карта расстояний на регулярной сетке, настоящие и предсказанные конечные
  положения. Общий масштаб цвета для сравниваемых моделей.
- Для выбранного блока — 20 карт активности и распределение значений
  перед активацией, чтобы видеть насыщение или неактивные нейроны.
- Среднеквадратичная величина градиента по параметрам каждого блока
  и по его скрытому состоянию; фиксировать момент измерения до обновления весов.
- Время обучения и оценки измеряются раздельно вместе с окружением запуска.

Убывание потерь на каждом шаге не гарантируется. Если обучающая ошибка
падает, а валидационная растёт, это отдельный результат для исследования,
а не повод скрыть неудобную кривую. Логарифмическая шкала доступна как
дополнительный режим; нулевые значения обрабатываются явно.

## Сравнения и итоговая оценка

До глубоких моделей проверить ответ без движения и аффинную модель 2→2.
Сравнивать активации, оптимизаторы и глубину, меняя сначала один фактор.
Повторять основные сравнения минимум на трёх начальных состояниях весов,
сохраняя одинаковые данные. Фиксированную ширину и сопоставимый бюджет
параметров считать разными экспериментами. Подбор настроек выполняется
по валидации; тест используется для итогового отчёта выбранной модели.
Если по тесту меняются настройки, он перестаёт быть независимым тестом.

## Сохранение результатов

Для каждого запуска сохранять конфигурацию, версию кода и генератора,
начальные состояния генераторов, число параметров, окружение и журнал метрик.
Предлагаемые форматы — JSON для конфигурации и CSV для числовых рядов.
Точный формат весов выбирается вместе с языком реализации.

Лучшие веса для оценки и последнее состояние для возобновления различаются.
Для точного возобновления нужны веса, состояния оптимизатора, номер шага,
состояния генераторов и положение в цикле обучения. Первую поддержку
возобновления можно ограничить границей эпохи и явно это документировать.
Файлы запуска хранятся вне отслеживаемых Git файлов, например в runs/.
