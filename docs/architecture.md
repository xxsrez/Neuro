# Проект архитектуры

Статус: предложение для согласования, реализации нет.
Задача: [движение точки](specs/point-motion.md).

## Размеры

Предлагается постоянная ширина 20 во всём скрытом ядре:

```text
вход (2) → линейный слой 2→20 → 10 остаточных блоков → линейный слой 20→2
                                       каждый: 20→20→20
```

Это 20 обучаемых линейных слоёв внутри блоков и 2 граничных слоя,
то есть 22 слоя с параметрами во всей модели. Если ограничение в 20 слоёв
относится ко всей модели, 9 блоков дают ровно 20 слоёв с параметрами.
Веса разных блоков независимы; каждый линейный слой имеет смещение.

Для 10 блоков: вход 60 параметров, блоки 10 × 840, выход 42;
всего 8 502 параметра. Для 9 блоков — 7 662 параметра.

## Блок и нелинейность

Предложение для первой версии:

```text
a = W1 * z + b1
q = activation(a)
r = W2 * q + b2
z_next = z + alpha * r
```

z, a, q, r — векторы из 20 чисел; W1 и W2 — матрицы 20×20.
alpha — фиксированный масштаб остаточной ветви; начальный кандидат 0.1,
который ещё надо согласовать и проверить. После сложения активации нет.
Граничные слои также линейные, без ограничения диапазона конечных координат.

По уточнению пользователя активация должна быть сменной: обязательно
сравнить ReLU, tanh и Swish. Первой предлагается Swish с фиксированным
параметром beta = 1; дополнительно предлагается Leaky ReLU.
В одном базовом эксперименте во всех блоках используется одна активация.

| Активация | Функция | Производная |
| --- | --- | --- |
| Swish, beta = 1 | x * s, где s = sigmoid(x) | s + x * s * (1 - s) |
| ReLU | max(0, x) | 1 при x > 0, иначе 0; в нуле принимаем 0 |
| tanh | tanh(x) | 1 - tanh(x)^2 |
| Leaky ReLU | x при x >= 0, иначе k*x | 1 при x > 0, k при x < 0; в нуле принимаем k |

Для Leaky ReLU предлагается фиксированное k = 0.01. Оно не связано
с масштабом остаточной ветви alpha. Эти активации не добавляют обучаемых
параметров. Обучаемые beta или k — отдельные возможные эксперименты.

Swish гладкая и не обнуляет всю отрицательную полуось, но её производная
тоже может быть малой. tanh насыщается при больших |x|. ReLU позволяет
наблюдать нулевые градиенты на отрицательных входах, Leaky ReLU — влияние
небольшого ненулевого наклона на этой половине оси.
Преимущество одной активации на нашей задаче заранее не установлено.

Для Swish sigmoid вычислять устойчиво: при x >= 0 использовать
1 / (1 + exp(-x)), иначе t / (1 + t), где t = exp(x).
Численные проверки производных ReLU и Leaky ReLU проводить отдельно
от точки излома; принятую производную в нуле проверять отдельным тестом.

Источник определения Swish:
[Ramachandran et al., Searching for Activation Functions](https://arxiv.org/abs/1710.05941).

Сравнение проводить на одинаковых данных, с одинаковыми начальными
весами, порядком примеров и бюджетом шагов, повторяя несколько начальных
состояний генератора. Измерять ошибку, градиенты и время на CPU.
Затем отдельно сравнивать с настройкой инициализации и скорости обучения
для каждой активации: один общий режим может быть выгоден одной из них.

## Прохождение градиента

Одинаковая ширина сама по себе не предотвращает затухание градиента.
Она позволяет выполнить z + alpha * r без дополнительного преобразования
размерности. Обычный backpropagation работает и при разных размерах слоёв.

Для входящего градиента g по z_next градиент по z равен:

```text
g_z = g + alpha * transpose(W1) *
          (activation'(a) ⊙ (transpose(W2) * g))
```

Здесь activation' применяется поэлементно, ⊙ — поэлементное умножение.
Первое слагаемое передаёт
градиент напрямую, второе идёт через обучаемую ветвь. Это не гарантия
от затухания или взрыва суммарного градиента: слагаемые могут усиливаться
или компенсироваться. Нужно измерять их и проверять численные градиенты.

Обоснование прямого пути в остаточных сетях:
[He et al., Identity Mappings in Deep Residual Networks](https://arxiv.org/abs/1603.05027).
Конкретный блок со сменной активацией и alpha выше — наше предложение
для учебного стенда.

## Выход и обучение

Функция потерь — средний квадрат ошибки двух конечных координат;
точная формула и порядок усреднения описаны в [обучении](training.md).
Скрытое состояние из 20 чисел не является физической точкой: соответствие
одного блока двум шагам симулятора не задано и не гарантируется.
Ранее обсуждавшийся вариант с 2-мерным состоянием между блоками здесь
заменён предложением с постоянной скрытой шириной 20.

В первой версии предлагается не использовать BatchNorm. Входы и ответы
масштабируются фиксированным делением на pi, как описано в
[спецификации данных](specs/point-motion.md). Предсказание одного примера
не должно зависеть от состава пакета. Нормализацию внутри блоков можно
добавить отдельным экспериментом после проверки базовой модели.

Инициализацию надо выбрать до реализации обучения: разные нейроны получают
разные случайные веса, все веса нельзя инициализировать одинаковыми нулями.
Начальные распределения и масштаб фиксируются в конфигурации запуска.
Численная точность для первых проверок предлагается 64-битная.

## Что осталось согласовать

- 9 или 10 двухслойных блоков; считать ли граничные слои в целевой глубине.
- Swish как первая активация, дополнительную Leaky ReLU и масштаб
  остаточной ветви; сравнение ReLU, tanh и Swish запрошено пользователем.
- Инициализацию весов; проверить предложенную нормализацию данных
  и параметры симулятора.
- Язык реализации и затем устройство вычислительного ядра.

До согласования архитектуры реализацию сети не начинать.
